# 체크카드 소비 자동 캡처 & 분석 에이전트

> 한 줄 요약: 실시간 스크린샷 OCR과 배치 PDF 파싱을 결합한 하이브리드 캡처 파이프라인으로 개인 소비 데이터를 자동 수집하고, LangGraph 멀티 에이전트가 분류·이상탐지·주간 브리핑을 수행하는 개인 금융 에이전트.

## 1. 프로젝트 개요

- **목표**: 체크카드 결제를 자동으로 캡처 → 카테고리 분류 → 이상지출 탐지 → 주간 소비 브리핑까지 사람 개입 없이 동작하는 파이프라인 구축
- **배경**: 카드사 결제 알림이 SMS를 지원하지 않고, iOS는 서드파티 앱의 push 알림 내용을 다른 앱이 읽을 수 있는 공식 API를 제공하지 않음. 이 제약 위에서 스크린샷 OCR 기반 캡처로 아키텍처를 설계함

## 2. 요구사항 반영 (부트캠프 스펙)

| 항목 | 내용 |
|---|---|
| 스택 | Python 3.11+, Docker/devcontainer, LiteLLM, Gemini API, Groq API, LangGraph, Chroma |
| 진행 방식 | 개인 repo에서 git flow 진행, 주 단위 컴포넌트 추가 |

## 3. 시스템 아키텍처

### 3.1 데이터 캡처 레이어 (2-트랙 하이브리드)

**실시간 트랙**
```
결제 알림 배너 → 스크린샷 → (뒤로 탭 x2, 화면 켜짐 상태 조건)
→ 최근 스크린샷 1건 가져오기 (30초 이내 필터)
→ Live Text OCR로 텍스트 추출
→ 정규식/조건문으로 파싱
→ FastAPI 웹훅으로 POST (Authorization 토큰 포함)
```

**배치 트랙 (백필/보정용)**
```
카드사 거래내역 확인서 정기 발급
→ PDF 파싱
→ 실시간 트랙에서 누락된 거래 보정
```

### 3.2 백엔드 (FastAPI)

- `POST /webhook/capture`: 캡처 요청 수신, 토큰 인증, payload 검증
- `POST /ingest/statement`: PDF 업로드 → 파싱 → DB 반영
- 정규화 로직: 원문 텍스트 → `{날짜, 가맹점명, 금액, 원본해시}` 구조화, 중복 방지는 원본해시 기준

### 3.3 저장소

- **관계형 DB** (SQLite로 시작, 필요시 Postgres): 정형 트랜잭션 레코드
- **Chroma**: 가맹점명/거래 설명 임베딩 저장 → 신규 거래의 카테고리 유사도 검색 + 자연어 질의응답용 인덱스

### 3.4 에이전트 레이어 (LangGraph)

| 노드 | 역할 |
|---|---|
| Categorization | 신규 거래 → Chroma에서 유사 과거 거래 검색 → LLM이 카테고리 확정 (애매하면 재확인 큐로) |
| Anomaly Detection | 최근 기간 대비 이상치 판단 — 룰 기반 임계치 + LLM 심각도 분류 병행 |
| Weekly Briefing | RAG로 해당 주 레코드 취합 → 소비 패턴 요약 생성 |
| Natural Language QA (stretch) | 자연어 질의에 응답 (예: "이번 주 배달비 얼마 썼어?") |

### 3.5 LLM 라우팅 (LiteLLM)

- **Groq**: 카테고리 분류처럼 저지연이 중요한 태스크
- **Gemini**: 주간 브리핑처럼 긴 컨텍스트 요약/설명형 태스크

### 3.6 알림

- Slack webhook: 이상지출 알림, 주간 브리핑 발송

## 4. 보안 설계

- webhook 인증: `Authorization` 헤더에 랜덤 토큰, 토큰 없는 요청은 거부
- 전 구간 HTTPS
- 원문 텍스트는 파싱 후 폐기, 구조화된 필드만 영속 저장
- payload 형식 검증으로 비정상 요청 필터링

## 5. 주차별 로드맵 (제안)

| 주차 | 목표 |
